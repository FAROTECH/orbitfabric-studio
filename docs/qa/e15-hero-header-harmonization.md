# E15 — Hero/Header Harmonization

Generated by: manual hardening slice  
Scope: OrbitFabric Studio stabilized desktop surfaces  
Status: draft until local QA and PR review pass

## 1. Intent

E15 is the first visible visual harmonization slice after the E14 token contract.

The goal is to align the hero/header grammar across stabilized Studio desktop
surfaces while preserving all runtime behavior, data semantics and layout
contracts.

## 2. Scope

E15 targets only the visible hero/header regions of these stabilized surfaces:

- Mission Overview
- Core Report Runner
- Data Products
- Generated Artifacts
- Scenario Evidence

E15 intentionally does not target Data Flow Workbench, Data Flow drawer or Data
Flow focus mode.

## 3. Files

E15 introduces:

- `src/studioHeroHeaderHarmonization.css`
- `docs/qa/e15-hero-header-harmonization.md`
- `tools/dev/check-studio-hero-header-harmonization.mjs`

E15 updates:

- `src/main.tsx`
- `package.json`

## 4. Design constraints

E15 must remain:

- CSS-only for runtime surfaces
- additive relative to the E14 `--of-visual-*` token contract
- scoped to existing stabilized desktop surface root classes
- free from OrbitFabric Core changes
- free from reference mission changes
- free from generated data changes
- free from command behavior changes
- free from scenario execution changes
- free from artifact generation changes
- free from graph/data-flow semantic changes
- free from private inference changes
- free from mobile/tablet scope expansion

## 5. Import position

`studioHeroHeaderHarmonization.css` is imported after the desktop envelope bridge
CSS files.

Reason:

- E14 tokens are available first
- E2-E12 desktop envelope contracts remain in force
- E15 can harmonize hero/header appearance without changing the lower-level
  envelope primitives or bridge CSS

## 6. Harmonization contract

E15 aligns:

- hero/header frame
- title block rhythm
- kicker/eyebrow treatment
- primary title treatment
- summary/lead treatment
- header side/posture rhythm
- Mission Overview report action affordance

E15 does not align:

- cards
- tables
- lists
- selected states
- status badges
- provenance badges
- raw/code blocks
- Data Flow drawer
- Data Flow focus mode
- graph/canvas visuals

Those remain future slices.

changes should not be committed.

## 8. Acceptance criteria

E15 is acceptable when:

- `src/studioHeroHeaderHarmonization.css` exists
- the CSS consumes E14 `--of-visual-*` tokens
- the CSS is scoped to the five stabilized non-Data-Flow surface root classes
- no Data Flow Workbench, drawer or focus selectors are targeted
- `src/main.tsx` imports the harmonization CSS after the desktop envelope bridge CSS
- `package.json` exposes `qa:studio-hero-header-harmonization`
- the QA script passes
- build passes
- the PR remains small and reviewable
